Use these synthetic inputs in a seeded demo. For a fresh local run, use `npm run demo` after `npm run build`. Each launch creates a fresh database. The hosted demo may already have applications, changed policies, withdrawn permissions, or simulated outages.

## 3. Scam Shield messages

Sign in as **Citizen**, open **Scam Shield**, and select **SMS**. Copy both fields exactly.

| Sender label | Synthetic message | Expected result |
| --- | --- | --- |
| `8171` | `Demo case received. Check status in the portal.` | **Known demo message** |
| `8171-HELP` | `Urgent! Pay a registration fee at http://relief-claim.example.invalid` | **Likely scam**. **Load demo SMS** fills both fields. |
| `COMMUNITY` | `Please visit the community desk tomorrow.` | **Unverified**. The report appears in the officer’s **Scam reviews** queue. |

If a generic message keeps showing **Unverified**, try the first row. The demo classifies an exact `8171` or `RAAST` sender with the word `demo` or `mock` and no warning signs as a known demo message.

## 4. Scam Shield document uploads

1. As **Citizen**, open **Apply for relief**. Keep the default name, enter `7000` for the amount, and select **Continue**.
2. Choose a **Sample scan condition**, select **Preview sample**, then **Download image**. You can repeat this step for each condition without submitting a relief application. Save the three images with distinct names.
3. Open **Scam Shield**. Set **Channel** to **Document sample**, upload the matching image, and select **Check document**.

| Image generated by the portal | Expected result |
| --- | --- |
| **Clear sample** | **Known demo message** badge and the explanation **The printed ID matches the signed synthetic QR.** |
| **Tampered sample** | **Likely scam** and an explanation that the printed ID differs from the signed demo QR. |
| **Blurry sample** | **Unverified** and referred for officer review. |

Generate and upload the card on the same site. Its QR is signed by that app environment. A real CNIC photo, unrelated screenshot, or a card signed with another environment’s key can show **Unverified**.

## 5. Relief application, review, and consent

1. For the automatic path on a fresh seed, sign in as `citizen@demo.pk`. Go to **Apply for relief** and enter **Amina Bibi**, **7000**, and **Clear sample**. Select **Submit application**. With the seed policy, active consent, and healthy mock rails, expect **Demo payment sent**.
2. For human review, use **Blurry sample** with the same name and amount. Expect **Human review**. Save the case number.
3. As **Officer**, find the case in **Review queue**, select **Inspect**, and optionally **Assign case**. Choose **Request more proof** and enter `Please attach a clear synthetic card.` in **Review notes**. Select **Record decision**.
4. As **Citizen**, open **My cases**, select **Add proof** on the same case, choose **Clear sample**, and submit. The original case returns to **Human review**. As **Officer**, choose **Approve**, enter `Verified the clear synthetic card.`, and record the decision. With payment consent active and Raast online, expect a mock transaction. Select **Close case**.
5. As **Citizen**, open **Data & consent** and withdraw **Eligibility registry** access. As **Auditor**, open **Decision traces** and inspect that case. Expect the trace to show the `BISP_POVERTY_SCORE` redaction. Grant **Eligibility registry** access again after the test.

For a newly registered citizen, first open **Data & consent**, grant **Identity verification**, **Eligibility registry**, and **Demo payment**, and use **Correct synthetic profile** with name **Demo Citizen**, district **Karachi**, income `12000`, and **Widowed or disabled** checked. Use **Demo Citizen** for the application name. A second submitted claim for the same profile within 30 days may go to human review even with a clear image. Use a fresh local demo if you want to repeat the first automatic payout.
